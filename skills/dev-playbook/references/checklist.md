# 收尾自检清单

每次改完代码交付前逐条过一遍。

## 代码

- [ ] 只改了与本次问题相关的代码，没顺手改无关部分。
- [ ] 改动尽量小而集中，方便 review 和回滚。
- [ ] 新增的 import / 依赖都已落地，没有悬空引用。
- [ ] 没有引入 linter 报错。

## 验证

- [ ] 已实际跑通（本地复现路径 / 功能操作 / 测试套件），不交"应该能跑"的代码。
- [ ] 涉及运行进程的，确认跑的是新进程/新产物。
- [ ] 修 bug 补了回归测试，加功能补了主路径测试。
- [ ] 跑全量测试无回归。

## 错误处理

- [ ] 错误信息按真实原因分级提示，没把多种可能混排。
- [ ] 给第三方 API 调用加了可重试特征识别 + 退避（如适用）。
- [ ] 间歇性失败有自动重试兜底，不把锅甩给用户配置。

## 文档

- [ ] 改了对外行为的，对应功能文档同步更新。
- [ ] 踩过的坑写进了项目问题文档或 `gotchas.md`。
- [ ] 没有把运行时易变值写死在手写文档里（交给自动生成）。

## 边界

- [ ] 没把某一种语言/框架的写法当成通用约束。
- [ ] 新功能没提前加"以后可能用到"的抽象。
- [ ] 改动范围和最初确认的需求一致，没跑题。

## 每次都要问

- 这个改动到底解决什么问题？一句话能说清吗？
- 我真的验证过了吗，还是"应该能跑"？
- 跑的是新代码吗？
- 错误信息能让人定位真实原因吗？
- 这次踩的坑记下来了吗？
