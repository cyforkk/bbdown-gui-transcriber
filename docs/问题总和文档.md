# 问题总和文档

## BBDown 不内置的分发问题

### 问题说明

将 BBDown 直接打进 exe 会带来许可证、体积、更新和调试复杂度问题。

### 处理方式

采用方案 B：不内置 BBDown，但支持同目录 `bbdown.exe` 自动检测。

### 检测顺序

1. exe 同目录 `bbdown.exe`。
2. 源码运行时项目根目录 `bbdown.exe`。
3. 系统 PATH 中的 `bbdown`。
4. 用户手动选择。

## Faster-Whisper 打包体积问题

### 问题说明

接入 Faster-Whisper 后，PyInstaller 打包体积从早期约 8.67 MB 增长到约 91.58 MB。

### 当前策略

接受该体积作为包含转文字依赖的 GUI 发布版，同时仍不内置 BBDown。

## 视频转文字能力边界

### 问题说明

视频转文字识别的是视频文件中的音频流，不识别画面文字，不做 OCR。无音频流或损坏视频会被记录为失败。

## 批量转文字失败处理

### 修复方式

转录前使用 `ffprobe` 校验媒体文件，单个文件损坏或识别为空不会中断整个批量任务。


## .NET global tool 版 BBDown 复制到 release 后不可用

### 问题现象

将 .NET 全局工具安装目录中的 `bbdown.exe` 复制到 `release` 后，GUI 优先使用该文件，但下载时报：

```text
The application to execute does not exist
```

### 原因

.NET global tool 的 `bbdown.exe` 不一定是完整便携版程序，复制到其他目录后可能找不到实际应用。

### 修复方式

GUI 检测到同目录 `bbdown.exe` 后会先执行 `--version` 校验。不可用时自动跳过，并回退到 PATH 中的 .NET 全局工具原始路径。

### 使用建议

方案一：继续使用原始 .NET 全局工具路径，不要复制该 `bbdown.exe` 到 release。

方案 B 只适合官方便携版或可独立运行的 `bbdown.exe`。


## 转文字任务 transcriber 局部变量遮蔽问题

### 问题现象

GUI 点击开始转文字后立即失败：

```text
转文字任务失败：cannot access local variable 'transcriber' where it is not associated with a value
```

### 原因

`run_transcription` 中使用局部变量名 `transcriber` 接收 `AudioTranscriber` 实例，遮蔽了导入的 `transcriber` 模块，导致 Python 在函数作用域内无法访问模块引用。

### 修复方式

将局部变量改名为 `audio_model`，保持 `transcriber` 始终指向模块；新增回归测试覆盖文件夹转文字路径。


## exe 中 Faster-Whisper VAD 模型文件缺失问题

### 问题现象

release exe 转文字时报错：

```text
faster_whisper/assets/silero_vad_v6.onnx failed. File doesn't exist
```

### 原因

`model.transcribe(..., vad_filter=True)` 需要 Faster-Whisper 包内的 `assets/silero_vad_v6.onnx`，PyInstaller 未默认收集该数据文件。

### 修复方式

打包命令增加：

```text
--collect-data faster_whisper
```

新版 release exe 已重新打包，体积约 92.61 MB。

## ffprobe 校验媒体文件时弹出黑色 CMD 窗口

### 问题现象

转文字前校验媒体文件时会短暂弹出黑色 CMD 窗口。

### 原因

`probe_media_file()` 调用 `ffprobe` 时未传入 Windows 隐藏子进程窗口参数。

### 修复方式

为 `ffprobe` 子进程添加 `STARTUPINFO`、`STARTF_USESHOWWINDOW` 和 `SW_HIDE`，保持输出重定向但不显示窗口。


## release exe 转文字时 CUDA cublas DLL 缺失问题

### 问题现象

选择文件夹批量转文字时，模型加载后单个文件转写失败：

```text
Library cublas64_12.dll is not found or cannot be loaded
```

### 原因

Faster-Whisper 使用 CUDA 时依赖 `nvidia-cublas-cu12` 和 `nvidia-cudnn-cu12` 包内的 DLL。源码环境可以从 `.venv` 找到这些 DLL，但 PyInstaller 单文件 exe 未自动收集 CUDA 二进制文件，并且运行时没有把 `_MEIPASS` 临时解包目录加入 DLL 搜索路径。

### 修复方式

打包命令增加：

```text
--collect-binaries nvidia.cublas
--collect-binaries nvidia.cudnn
```

运行时优先把 PyInstaller `_MEIPASS` 临时目录加入 CUDA DLL 搜索范围，再调用 `os.add_dll_directory()` 和补充 `PATH`。


## 单文件 release exe 启动过慢问题

### 问题现象

双击 `BilibiliDownloaderUI.exe` 启动很慢。

### 原因

单文件 PyInstaller exe 包含 CUDA、cuBLAS、cuDNN、Faster-Whisper 等大依赖，体积超过 1GB。`--onefile` 每次启动都要先解压内部文件到临时目录，导致启动耗时明显。

### 修复方式

打包方式改为 PyInstaller `--onedir` 文件夹版发布，生成 `release/BilibiliDownloaderUI/BilibiliDownloaderUI.exe`。大依赖保留在 `_internal` 等目录中，启动时不再重复解压整个大包。


## release 大文件进入 Git 历史导致 push 失败问题

### 问题现象

将包含 CUDA/Faster-Whisper 依赖的 `release/` 发布成品提交到 git 后，推送 GitHub 失败或连接被重置。

### 原因

文件夹版发布包包含大量 DLL 和依赖文件，仓库对象一度达到 GiB 级别。GitHub 普通源码仓库不适合直接存放这类发布成品。

### 修复方式

从 git 历史中移除 `release/`，并在 `.gitignore` 中忽略发布成品。源码仓库只保存代码、测试、文档和构建脚本；发布成品压缩为 zip 后通过 GitHub Releases 分发。
