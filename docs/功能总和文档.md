## 标准 GitHub 项目结构

- `src/bbdown_gui/`：应用源码包（app.py 含选择弹窗、downloader.py 含 WBI 签名与风控重试、transcriber.py）。

## BBDown 自动检测

### 功能说明

采用方案 B：不内置 BBDown。自动检测当前工作目录、用户 `.dotnet/tools`（`dotnet tool install` 安装位置）、应用目录和 PATH；本地打包后也支持同目录 `bbdown.exe`。目录扫描忽略文件名大小写（`bbdown.exe` / `BBDown.exe` / `bbdown` 均命中）。

### 检测顺序

1. 当前工作目录下的 `bbdown.exe` / `BBDown.exe`（忽略大小写）。
2. 用户目录 `.dotnet/tools`（忽略大小写）。
3. exe 同目录 `bbdown.exe`（源码运行时为项目根目录）。
4. 系统 PATH 中的 `bbdown`。
5. 用户手动选择。

## 下载功能

支持收藏夹/视频合集/单视频下载，音频/视频二选一，停止下载，隐藏 CMD 窗口。

### B 站风控与自动重试

B 站对收藏夹/合集 API 有间歇性风控（无 Cookie 的裸请求偶尔被拒，返回 HTTP 412 或风控拦截页）。程序已内置自动重试：识别风控特征错误后最多重试 3 次，退避 2s/4s；非风控错误不重试。公开收藏夹无需登录即可拉取，重试期间用户只需等待。

### 下载前视频选择弹窗

选择「收藏夹链接」或「视频合集链接」并点击开始下载后，先在后台分页拉取视频列表（每页完成输出「已获取 N 个视频」进度日志，大列表不会显得卡死），随后弹出「选择要下载的视频」窗口：

- 列表默认全选，显示序号、BV 号和标题，使用 Listbox 多选控件，自带滚动条。
- 多选语义同 Windows 资源管理器：单击替换为当前项、Ctrl+单击追加或切换该项、Shift+单击选中锚点到当前的连续范围；顶部提供「全选」「全不选」「反选」按钮和实时「已选 N / 总数（显示 M）」计数。
- 搜索框输入关键词实时过滤列表（匹配 BV 号或标题，忽略大小写）；「全选 / 全不选 / 反选」作用于当前过滤可见的项，便于在大列表中按关键词批量选择。
- 点击「开始下载所选」只下载勾选的视频；全不选时点确认会提示至少选一个。
- 点击「取消」或关闭窗口则终止任务，不进入下载。

单个视频下载不经过选择弹窗，直接开始。

### 大列表拉取策略

分页拉取以 API 报告的总数为目标（合集 `data.page.total` / 收藏夹 `data.info.media_count`），按 bvid 去重；短页（返回条数不足 page_size）不会提前终止，仅当某页零新增、取满总数或超过 500 页安全上限时停止。若实际获取数小于 API 报告总数，GUI 通过 `on_warning` 回调把警告输出到日志区（如「警告：合集共 1111 个视频，实际获取到 1108 个，其余可能是失效或受限视频。」）；命令行模式则输出到 stderr。失效/受限视频接口不返回，属 B 站接口行为。实测 1111 个视频的合集可拉取到 1108 个，差额为 3 个失效稿件。

### 视频合集来源

GUI「下载来源」增加「视频合集链接」，链接形如：

```text
https://space.bilibili.com/<mid>/lists/<id>?type=season
```

解析逻辑（`downloader.parse_collection_id`）从路径中提取 `mid` 与合集 `season_id`，再调用合集接口 `https://api.bilibili.com/x/polymer/web-space/seasons_archives_list`（带 WBI 签名，失败时自动回退未签名请求与旧接口 `x/polymer/space/seasons_archives_list`）分页拉取合集内视频 `bvid` 列表（`fetch_collection_videos`），最后复用 `download_all` 批量下载。

## 转文字功能

支持音频和 `.mp4` 视频转文字。视频转文字识别的是音频流，不做 OCR。支持文件夹批量转换，模型只加载一次。

## 打包功能

通过 `uv run python scripts/build_exe.py` 打包新版 GUI。当前 release 使用文件夹版发布，包含 Faster-Whisper/CUDA 相关依赖，不包含 BBDown 本体。


## 文件夹版 release 发布

打包方式从 PyInstaller `--onefile` 改为 `--onedir`，生成 `release/BilibiliDownloaderUI/BilibiliDownloaderUI.exe`。

这样 CUDA、cuBLAS、cuDNN、Faster-Whisper 等大依赖保留在文件夹中，双击启动时不需要每次解压 1GB 以上单文件 exe，启动速度更快。


## GitHub Releases 发布方式

源码仓库不再提交 `release/` 发布成品，只保留源码、测试、文档和打包脚本。

Windows 发布包通过以下流程生成：

```bat
uv run python scripts\build_exe.py
```

生成 `dist/BilibiliDownloaderUI/` 后，将整个文件夹压缩为 `BilibiliDownloaderUI-windows-x64.zip`，再上传到 GitHub Releases。

这样可以避免 CUDA/Faster-Whisper 大文件进入 git 历史，保持源码仓库轻量。


## 轻量下载模式和转文字 extra

项目默认依赖改为轻量下载模式，`uv sync` 只安装 GUI 和下载功能所需依赖，不安装 Faster-Whisper/CUDA 大依赖。

需要转文字时执行：

```bat
uv sync --extra transcribe
```

`transcribe` extra 包含 `faster-whisper`、`nvidia-cublas-cu12` 和 `nvidia-cudnn-cu12`。未安装该 extra 时，下载功能仍可正常使用；点击转文字会提示安装命令。

本地打包也分为两种：

```bat
uv run python scripts\build_exe.py --edition lite
uv sync --extra transcribe
uv run python scripts\build_exe.py --edition full
```
