# 本地打包指南

把 BBDown GUI 打包成 Windows exe 文件夹版发布的操作指南。理论背景（为什么用文件夹版而非单文件版）见 `PyInstaller文件夹版和单文件版区别.md`。

## 前置条件

- 已安装 `uv`（项目用 uv 管理依赖与运行）。
- 打包 full 版需要本机已装 CUDA 运行时（cuBLAS / cuDNN），否则转文字功能不可用；lite 版无此要求。
- 打包脚本：`scripts/build_exe.py`。
- 发布说明模板：`scripts/release_readme.txt`（打包时自动复制为产物里的 `README.txt`）。

## 打包命令

在项目根目录执行：

```powershell
cd d:\bbdown脚本
uv run python scripts/build_exe.py --edition full
```

`--edition` 取值：

| 取值 | 包含内容 | 体积 | 适用 |
| --- | --- | --- | --- |
| `full`（默认） | 下载 + 转文字（Faster-Whisper + CUDA + cuBLAS + cuDNN） | 大（约 900MB+） | 需要转文字、本机有 CUDA |
| `lite` | 仅下载功能 | 小 | 仅下载、轻量分发（GitHub Release 用此版） |

## 打包流程

`scripts/build_exe.py` 的 `main()` 依次执行：

1. 构造 PyInstaller 命令（`--onedir --noconsole --clean --name BilibiliDownloaderUI`）。
2. full 版额外加 `--collect-data faster_whisper`、`--collect-binaries nvidia.cublas`、`--collect-binaries nvidia.cudnn`。
3. 执行 PyInstaller，产物输出到 `dist/`。
4. 校验发布目录完整性：必须存在 `BilibiliDownloaderUI.exe`、`_internal/_tcl_data`、`_internal/_tk_data`（Tkinter 运行时必需，缺失会启动失败）。
5. 把 `scripts/release_readme.txt` 复制为 `dist/BilibiliDownloaderUI/README.txt`。

任一步失败会打印原因并返回非 0 退出码。

## 产物结构

```text
dist\
└─ BilibiliDownloaderUI\
   ├─ BilibiliDownloaderUI.exe   ← 启动入口
   ├─ README.txt                 ← 用户说明（自动生成）
   └─ _internal\
      ├─ _tcl_data\              ← Tkinter 运行数据
      ├─ _tk_data\
      ├─ python313.dll
      ├─ faster_whisper\         ← 仅 full 版
      ├─ nvidia\                 ← 仅 full 版（cuBLAS/cuDNN DLL）
      ├─ onnxruntime\
      ├─ numpy\
      └─ ...
```

启动方式：双击 `dist\BilibiliDownloaderUI\BilibiliDownloaderUI.exe`。

**注意**：必须保留整个 `BilibiliDownloaderUI` 文件夹完整，不能只复制 `BilibiliDownloaderUI.exe`，否则会因找不到 `_internal` 依赖而启动失败。

## 验证打包成功

控制台输出应包含：

```text
已写入发布说明：d:\bbdown脚本\dist\BilibiliDownloaderUI\README.txt
打包完成：d:\bbdown脚本\dist\BilibiliDownloaderUI
启动文件：d:\bbdown脚本\dist\BilibiliDownloaderUI\BilibiliDownloaderUI.exe
```

启动后点「检测 BBDown」应能命中用户目录 `C:\Users\<用户名>\.dotnet\tools\BBDown.exe`（或 exe 同目录的 `bbdown.exe`）。合集下载、视频选择弹窗、风控自动重试等行为与源码一致。

## 分发

1. 把整个 `dist\BilibiliDownloaderUI` 文件夹压缩为 `BilibiliDownloaderUI-windows-x64.zip`。
2. 上传到 GitHub Releases（lite 版可由 CI 自动构建，见 `GitHubActions自动发布流程.md`）。
3. 源码仓库不提交 `dist/`、`build/`、`release/`（已在 `.gitignore` 排除）。

## 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动报 `_tcl_data` 缺失 | 发布目录不完整 | 重新打包，确认校验步骤通过 |
| full 版转文字报 `cublas64_12.dll` 缺失 | CUDA DLL 未收集 | 确认 `--collect-binaries nvidia.cublas/cudnn` 在命令中 |
| full 版转文字报 `silero_vad_v6.onnx` 缺失 | VAD 模型未收集 | 确认 `--collect-data faster_whisper` 在命令中 |
| exe 启动慢 | 单文件版才会慢 | 文件夹版不会，确认没误改成 `--onefile` |
| BBDown 检测弹警告 | 同目录无 bbdown.exe 且 PATH 无 | 把 `bbdown.exe` 放到 exe 同目录，或依赖用户目录 `.dotnet/tools` |

## 与 CI 发布的关系

GitHub Actions（见 `GitHubActions自动发布流程.md`）只构建 **lite 版** 上传 Release。full 版体积过大，需本地打包，不通过 Release 分发。本地打包的 full 版可自行通过网盘等方式分发。
